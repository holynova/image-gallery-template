从输入
到上线

不需要从空白页面开始。把内容放进契约，运行一条条可验证的命令，最后选择一个发布目标。

01 / BRIEF

说清楚主题

给网站名称、主题、图片目录和想要的气质。其他字段可以使用默认值。

02 / INGEST

放入原图

原图进入 incoming/，配置文件记录栏目、排序和描述。

03 / VERIFY

构建与检查

处理媒体、生成 manifest，检查引用、alt、产物体积和页面结构。

04 / SHIP

选择一个平台

GitHub Pages 或 Cloudflare Pages。账号授权始终由你掌握。

你得到的
不是一个壳

页面、内容、媒体、分析和发布被拆成可以独立检查的层。换主题，不必重新发明整套工程。

01 · MEDIA

响应式媒体

AVIF、WebP、JPEG 多宽度变体，首图优先，其余懒加载并按需预取。

02 · UI

可访问画廊

筛选、灯箱、键盘与触摸导航，焦点返回，减少动态效果，适配手机屏幕。

03 · CONTENT

内容契约

站点、栏目、图片元数据和生成 manifest 有稳定 schema，AI 不用猜文件关系。

04 · ANALYTICS

Umami 可选

不配置就不加载。配置后只发送 gallery、collection 和 image id 等非 PII 事件。

05 · QA

发布前门槛

validate、check、测试和生产构建都能在本地重复运行。

06 · AI

仓库级 Skill

$build-gallery 负责 intake、媒体处理、预览、检查和部署选择。

开始工作

模板把“人能读的需求”和“机器能验证的输入”分开。AI 负责补全表达，构建脚本负责保持事实。

输入目录

把图片放在 incoming/，把网站信息放在 content/。删除示例素材后，目录仍然可以从零生成。

文件名可以包含中文；处理脚本会生成稳定 slug、hash 和每个尺寸的来源。

project mapcontent contract

让 AI 读懂
你的意图

启动提示词保持短小。真正的规则在仓库内，换一个模型或换一次对话，流程也不会丢。

从一句话开始

把主题、图片位置、站点名和发布目标告诉 AI。缺少账号时，AI 应该停在授权边界前。

请使用 $build-gallery skill 处理这个图片画廊仓库。
主题：城市夜行摄影；图片位于：incoming/night-walk；站点名：城市夜行。
请自动整理栏目、生成简短文案和准确 alt，运行 ingest、validate、check、test 和 build。
完成桌面与移动端预览检查后，部署到 GitHub Pages；缺少外部账号参数时再询问我。

选一个
发布出口

构建产物是静态文件。平台只是出口，内容和生成逻辑仍然留在你的仓库里。

GitHub Pages

适合开源项目和个人站点。工作流默认手动触发，仓库名会自动成为 base path。

Settings → Pages → GitHub Actions

Cloudflare Pages

适合需要全球边缘网络和分支预览的静态站点。只提供项目名，不把 token 写入代码。

npm run deploy:cloudflare -- --project-name your-site

常用命令

每一步都可以单独运行。发布前至少完成 ingest、validate、check、test 和 build。

npm install安装 Astro、Sharp 和校验依赖
npm run ingest扫描原图并生成响应式媒体
npm run validate检查配置、引用、尺寸和产物
npm run check运行 Astro / TypeScript 检查
npm test运行 slug、schema、pipeline 测试
npm run build生成可发布的 dist/ 静态站点
